# Changelog

All notable changes to ArterIA are documented in this file, in plain language for anyone following the project (not just contributors). Versioning follows [Semantic Versioning](https://semver.org/). 1.0 marks the first runnable release (first real SJC network built and rendered); before that, versions marked planning milestones.

## [1.7] - 2026-10-29

### Added

- **P3.6 scenario config schema.** `ScenarioConfig`/`load_scenario_config` (`arteria/config.py`) validate a baseline scenario's net/TAZ/route/additional files, time window and seed/replication policy (rejecting a seed count that doesn't match `replications`) — schema only, same minimal pattern as the P5.1 intervention-catalog schema, with no CLI command. A real `cities/sjc/scenarios/baseline/` instance still needs real route files, which don't exist until P3.2's gravity model and P3.3's real run are unblocked (see below).

## [1.6] - 2026-10-29

### Added

- **P3.2 production weights done; P3.3 trip-generation mechanics done.** `arteria demand population --city sjc` (`arteria/demand/population.py`) downloads the real IBGE Censo 2022 setor (census-tract) GeoPackage and sums population into the P3.1 TAZs: a=13,499, b=36,391, c=24,516, d=22,702, external=599,946 (1,554 SJC census tracts, total 697,054). New `ibge-censo-populacao-setores` entry in `cities/sjc/data-manifest.yaml`. `arteria/demand/trips.py` wraps the real `od2trips`, `duarouter` and `routeSampler.py` SUMO tools (new `arteria demand od2trips`/`duarouter`/`routesampler` CLI commands) behind the same injected-binary seam as the network build code (ADR 0009); a desk-only round trip (toy OD matrix -> trips -> routes -> counts-sampled routes) runs against the real SUMO 1.28.0 install. Both items' real run against SJC stays blocked: P3.2's attraction-side weight (Geosanja zoning proxy) still hasn't been downloaded, and P3.3 additionally needs real traffic counts (`traffic-counts`, still `deferred`) — see `docs/roadmap.md`'s P3.2/P3.3 status notes and `.claude/napkin.md`.

## [1.5] - 2026-10-29

### Added

- **Phase 3 (demand and baseline scenario) started: TAZ zoning (P3.1) done.** `arteria demand taz --city sjc` (`arteria/demand/zoning.py`) assigns every network edge to one of the four aerial-verified study-area polygons (`cities/sjc/study-areas.geojson`) or to a catch-all `external` zone, by point-in-polygon test of the edge's midpoint, and writes a SUMO `.taz.xml`. Run for real on the unified net (14,225 edges): a=1,146, b=3,020, c=1,786, d=1,103, external=7,170 — no zone empty. Output is gitignored (reproducible from committed inputs); see `cities/sjc/demand/README.md`.
- **ADR 0017 (Proposed): zoning and trip-generation data sources.** Fills the gap ADR 0013 left open — *which* data backs the gravity-model demand fallback. Proposes IBGE Censo 2022 population by census tract for production (self-service, same no-contact precedent as the existing `ibge-faces-logradouros` source) and the already-downloaded Geosanja zoning/land-use layer as an attraction proxy, since no public jobs/employment dataset is reachable without contacting an agency. The real census download, the zone-weight join and the gravity model itself (P3.2) are not implemented yet.

## [1.4] - 2026-10-28

### Changed

- **Phase 2 (network build) exit criteria met; phase marked done.** `arteria network rebuild --city sjc` reproduces the pinned network from the OSM snapshot; validation is 0 errors (127 non-blocking warnings); the four study-area corridors are aerial-verified (2026-10-27); and the network's geometry and street names are cross-checked against IBGE and GeoSanja ([1.2], [1.3]). `docs/roadmap.md`, `README.md` and `README-eng.md` are updated to match. Manual `netedit` junction fixes (P2.4) and the GTFS public-transport layer (P2.6) stay open as deferred, non-blocking items.

## [1.3] - 2026-10-28

### Fixed

- **`netconvert` double-escaped apostrophes (and other XML special characters) in street names.** A literal `'`, `&`, `"`, `<` or `>` in an OSM `name` tag came out of `netconvert` 1.28.0 double-escaped (e.g. a plain apostrophe became `&amp;apos;` instead of nothing, since an apostrophe needs no escaping in a double-quoted XML attribute) — confirmed with a minimal two-way OSM fixture against the real binary. `arteria network build`/`rebuild` now corrects this automatically after every `netconvert` run. The real SJC network was rebuilt with the fix (58 double-escaped characters corrected across 3 street names, e.g. "Rua Armando D'Oliveira Cobra"; no edges, lanes or junctions changed) and the pinned snapshot was re-pointed at the corrected network. The cross-check now matches one more street name (544 instead of 543) now that its name compares correctly.

## [1.2] - 2026-10-28

### Added

- **Public street data downloaded and cross-checked against OpenStreetMap; P2.1 and P2.7 done.** IBGE 2022 street faces (the São Paulo state file, which contains São José dos Campos) and the GeoSanja road layers were downloaded; `cities/sjc/data-manifest.yaml` records the source files and their hashes. New `arteria network crosscheck --city sjc` runs a corridor-level name and geometry cross-check against both sources: 543 street names matched, with a median offset of about 3 m between OpenStreetMap and the reference. New `arteria network render --city sjc` draws the network with the study-area outlines (one overview, one per area). Results are in `data/crosscheck/crosscheck.md` and `data/renders/` (local only, gitignored).

## [1.1] - 2026-10-27

### Added

- **Phase 2 (network build) reproducibility is in place.** `arteria network rebuild --city sjc` checks the pinned OpenStreetMap snapshot (`cities/sjc/network/osm-snapshot.yaml`: Geofabrik Sudeste file of 2026-10-25, its checksum, and the checksum of the clipped city extract), clips, runs `netconvert`, validates, compares the result with the pinned reference network and writes a provenance record. Run for real at the desk: the rebuilt network is identical to the existing one (14,225 edges; netconvert's timestamp comment is ignored when comparing, so the raw file hash changes every build but the content hash does not), a second run reproduced it again, and validation shows 0 errors and 127 warnings (dead ends, signal junctions nobody uses, and 93.1% of junctions in the main routable component). `arteria osm fetch` now refuses a source or extract that differs from the pin (`--update-snapshot` re-pins on purpose). New `arteria network diff --old A --new B` lists edges, lanes and junctions added, removed or changed (JSON and markdown); as a sanity demo, the old B-only network against the unified one shows 12,175 edges added, 24 removed and 137 changed. Network corrections can now be kept as small plain-XML patch files listed in `cities/sjc/network/patches/manifest.yaml` (none needed yet; SUMO 1.28 has no patch option, so a second `netconvert` pass applies them). A desk-only test checks that every corridor edge exists in the built network (it does). No public SJC GTFS feed was found, so the public-transport layer (P2.6) waits on data.
- **Owner aerial check of all corridors passed (2026-10-27).** Corridors A, B, C, D, the A-B link and the extended B and C study areas were checked against aerial imagery in Google Earth and are good for now, including C's extension to the west/south-west. The corridor README and `candidate-corridors.md` no longer call them drafts; the unified network's geometry on these corridors counts as aerially verified for the Phase 2 exit criterion.
- **Draft centrelines for corridors C, D and A, a derived B centreline, and a route joining A to B (`cities/sjc/corridors/`).** Each is an ordered list of real edges of the unified network, routed in both directions, with GeoJSON, a Google Earth KML (study-area polygons plus coloured lines) and a PNG overview for the owner's aerial-imagery check. A and B connect in both directions (883 m one way, 1,286 m the other). B itself only had a polygon before, so its centreline is new and unchecked; D and C are areas and were drawn as best-guess spines (see the README there for assumptions). After the owner's first look, the C and B study areas were extended (2026-10-27): C now also covers Parque Vicentina Aranha, Av. Barão do Rio Branco, R. Madre Paula de São José and R. José Francisco Alves (1.5 to 4.2 km2; these streets lie west/south-west of the old polygon), and B continues south through Jd. Satélite along Av. Cassiopéia and Av. Perseu (5.3 to 7.7 km2). The unified network was rebuilt for the larger envelope (14,225 edges, 6,655 junctions, 93% of junctions in the main routable component) and new C and B legs were drawn on those streets. A and D polygons and the A-B link are unchanged.
- **Confirmed: the two traffic-light clusters without a signal program are harmless in SUMO.** Running SUMO 1.28.0 on the real SJC network (`sumo -n cities/sjc/network/sjc.net.xml --end 1`, and a 100 s run with the random demo traffic) printed no warnings or errors. The two bicycle-crossing clusters flagged by the validator load as ordinary unsignalised junctions, so the validator warning stays a warning and needs no fix.
- **Desk check of the public street-network sources for SJC (partial).** The city's GeoSanja portal now lives at geo.sjc.sp.gov.br as a new web map whose layer list loads only in a browser, so whether it still offers Master Plan/zoning layers or a road-network layer is not yet confirmed. IBGE's street-faces page blocks scripted access and the 2022 download folder could not be found, so its "preliminary" status is also unconfirmed. In the OpenStreetMap candidate-B extract, main roads are well tagged (name, lanes, speed) but side streets mostly lack lane and speed tags (4-5%); whether streets are missing altogether was not measured. Details are in `cities/sjc/data-manifest.yaml`.
- **Networks for candidates D, C and A, and a decision to use one unified SJC network (ADR 0016).** Clipped OSM extracts and `netconvert` networks now exist for all four candidates (SUMO 1.28 from the `eclipse-sumo` wheel; B's result reproduced exactly). Because B and C touch A and D sits about 0.3 km from it, the project builds a single network over the envelope of all four polygons (11,035 edges, 94% in the main routable component, against 70-88% for the separate ones) and treats B, D, C and A as evaluation areas inside it. New `arteria osm fetch --candidate all` clips that envelope. Generated networks are gitignored;
- `nox -s smoke` now runs for real: it builds a small hand-written toy network (`tests/fixtures/smoke/`) with `netconvert`, simulates it with `sumo`, and fails on any SUMO error or fewer than 10 completed trips. Verified passing (50 vehicles) on the desk, which satisfies the second half of the roadmap's P0 exit criterion. It still skips cleanly where no SUMO binary is installed.

### Changed

- Roadmap local items reconciled with ADR 0014 (WSL2-only desk): L4 (long paths) and L5 (Defender exclusions) are marked not applicable, and L7 (long-run power hygiene) and L18 (scheduled overnight runs) now point at `scripts/linux/` helpers using `systemd-inhibit` and systemd timers/`cron` instead of `powercfg` and Task Scheduler. ADR 0002's `scripts/` description is updated to match. The scripts themselves are not written yet.
- `arteria network validate` now works on real SUMO networks (fixing the first-run findings below): on the real candidate-B network it goes from 729 errors / 7,562 warnings to 0 errors. The never-applicable `oneway_status` check is gone (one-way vs. two-way edges are now counted by opposite-edge pairs and printed as stats); internal `:` edges are skipped; connectivity is judged by strongly connected components and reports the main component (770 of 986 junctions) and the orphans outside it as one summary warning instead of hundreds of errors; dead ends at the study-area clip boundary are reported separately as `info` (`clip_boundary_dead_end`) from true traps (`dead_end`); and a `traffic_light` junction without a `<tlLogic>` is only an error if some connection is bound to it (the two bicycle-crossing clusters are warnings: no connection uses them, so SUMO treats them as unsignalised -- confirmed by running `sumo`, see below). The validator is now also tested against a real 100 m slice of the candidate-B network (`tests/fixtures/real-slice-sjc-b.net.xml`).
- Dev PC benchmark against the roadmap's 8-core / 32 GB guideline (`docs/local/dev-pc-benchmark.md`): the desk PC (6 cores / 12 threads, WSL2 capped at 10 GB RAM, 831 GB free disk) is fine for network builds, single runs and overnight calibration at about 4 workers, but the planned 10k-run NSGA-II campaign would take well over a day and needs a smaller first campaign or a cloud/cluster node. SUMO step rates were not measured (no SUMO binary in the measuring session).

## [1.0] - 2026-10-26

### Added

- **First real end-to-end run: São José dos Campos is visible in `sumo-gui`.** At the desk (WSL2), the full chain ran against real tools and data for the first time: `arteria studyarea build` (Nominatim) -> `arteria osm fetch --candidate b` (Geofabrik Sudeste extract clipped by `osmium`) -> `arteria network build` (`netconvert`) -> `sumo-gui` with 1,800 uncalibrated `randomTrips.py` vehicles (415 further trips were unroutable and discarded). Only candidate B (Av. Andrômeda <-> DCTA / Jardim Satélite) is rendered so far; candidates D, C and A have polygons but no network yet. This is a routability and visual check, not a calibrated baseline or a validated corridor choice.
- First-run findings on the network validator (`arteria network validate`, 729 errors / 7,562 warnings on the real candidate-B network), recorded as open work rather than fixed: the 7,522 `oneway_status` warnings are a false positive (SUMO's `.net.xml` has no `oneway` attribute, so that check can't work on real networks); the 727 `connectivity` errors are measured from a single start junction on a clipped extract and so are expected, not real disconnections; the 40 `dead_end` warnings are mostly clip-boundary edges; and the 2 `traffic_light_logic` errors are real netconvert output — two bicycle-only crossing clusters typed `traffic_light` with no `<tlLogic>` (2 of 18 traffic-light junctions), probably harmless but unverified. The validator was tuned to toy fixtures; adapting it to real networks is tracked in `.claude/napkin.md`.
- ADR 0014 (desk environment: WSL2 as the sole primary OS): the desk machine runs WSL2 (Ubuntu) only, not split with native Windows — the repo, `ARTERIA_DATA`, and `ARTERIA_PRIVATE` live on WSL2's native Linux filesystem, SUMO's GUI tools (`sumo-gui`/`netedit`) run inside WSL2 via WSLg, and Windows is only reached into for occasional Windows-only tools. Avoids the Windows/WSL2 9P filesystem performance penalty for `make`/`git`/`pip`-heavy work and the dual-install version-drift risk the roadmap previously flagged. `docs/roadmap.md`'s "Local features" intro and `docs/local/setup-and-daily-commands.md`'s one-time setup steps (long paths, Defender exclusions, environment variables) are updated to match; reconciling the remaining Windows-native `L<n>` scripts (power hygiene, scheduled runs) is tracked in `.claude/napkin.md`.

### Fixed

- `arteria network build` now converts a `.osm.pbf` input to OSM XML with `osmium cat` before calling `netconvert`, which cannot read PBF (first real run failed with "invalid multi-byte sequence"). The other default `netconvert` flags were accepted as written.
- Three SJC study-area geocoding queries that failed or landed in the wrong place on real Nominatim (DCTA street address, "Bairro São Bento", plain "Centro", which resolved ~30 km north) now use working landmark queries in `cities/sjc/study-areas.yaml`.
- `ARTERIA_DATA` is now a gitignored `data/` folder inside the repo checkout (still on WSL2's native filesystem, per ADR 0014); generated SUMO network files (`.net.xml`, `.osm.xml`, `.rou.xml`, `.trips.xml`) are gitignored too.

## [0.3] - 2026-10-25

### Added

- Catalog-entry dispatcher (`arteria/interventions/apply.py`, roadmap R18/P5.2-P5.3): `apply_intervention()` turns one `CatalogEntry` into a call to the right transform (`one_way.py`, `turn_restriction.py`, `signal_retiming.py`, or `lane_restriction.py` for `bus_lane`/`protected_bike_corridor`/`pedestrian_street`/`lane_reallocation`, applying it across every one of the entry's `target_edges` in turn), reading the edge/junction ids and parameters straight off the entry the way a real catalog file carries them. Closes the gap between the P5.1 schema and the P5.2 transforms, which until now had no code connecting them. Raises `UnsupportedInterventionTypeError` for the three catalog types with no transform yet (`reversible_lane`, `new_connector`, `transit_signal_priority` — each needs a network edit beyond plain-XML attribute/element removal or detector/TraCI wiring) rather than guessing. Tested against `tests/fixtures/toy-catalog.yaml`'s three entries plus a signal-retiming entry, on matching toy networks.
- ADR 0013 (no real OD microdata; synthetic, count-calibrated demand only) accepted: the owner permanently declined to ever request, use, publish, or derive from real OD survey microdata, for privacy/re-identification reasons rather than just commercial/contractual ones. `cities/sjc/data-manifest.yaml`'s `od-survey-microdata` entry moves to a new `status: declined` (`arteria/config.py`'s `ManifestStatus`), and its ask is dropped from the Ipplan draft request. Demand generation (roadmap P3) relies on a synthetic, `routeSampler`-calibrated scenario instead, with explicit scope limits (not adequate for equity-by-neighborhood, new-connector network-wide benefit, or emergency-evacuation claims) and required terminology ("synthetic traffic scenario calibrated to observed flows", never "the real traffic of SJC").
- ADR 0003 (city config and data schema) accepted: the owner proceeds without waiting for real traffic counts/OD data to use fields like `city.yaml`'s `time_windows` — accepted qualitatively, from direct local experience, that corridors A (Anel Viário/Dutra spillover) and D (Jardim Colinas roundabout) carry heavy peak-hour traffic. The am-peak window stays a best guess pending real P4 calibration.
- Repository visibility and licensing decided (`docs/adr/0012-repo-visibility-and-licensing.md`): the GitHub repo is public; code (`arteria/`) is licensed under Apache License 2.0 (`LICENSE`); documentation, the research brief, and published derived data are licensed under CC BY 4.0 (`LICENSE-DOCS.md`). Resolves roadmap open questions 5 and 7. Does not change the per-source `visibility: public|restricted` field in `data-manifest.yaml` or its pre-commit safety net (ADR 0003/0004) — a data source an agency restricts still can never be committed, regardless of the repo's own license.
- Run provenance manifests (`arteria/provenance.py`, roadmap P0.7): a reusable schema and helper functions so that every future simulation, calibration, or optimizer run (`arteria sim run`, `arteria calibrate ...`, `arteria optimize run` — desk-only, Phases 3/4/7) can write a `manifest.json` recording the git commit, SUMO version, random seed, a hash of the config used, and checksums of its input files, matching the `runs/<city>/<run-id>/` layout in `docs/roadmap.md`. Tested on toy fixtures only; no command calls it yet.
- Network validation checks (`arteria/network/validate.py`, roadmap R4/P2.5): parses a `.net.xml`-shaped document and reports, without stopping at the first problem, on connectivity, dead ends, lane counts, missing one-way markers, dangling or out-of-range connections, non-positive speed limits, and traffic-light junctions missing their signal program. Tested against hand-written toy fixtures (one clean, one with a deliberate issue per check); the real network build and visual check stay at the desk.
- GEH and travel-time goodness-of-fit metrics (`arteria/calibration/goodness_of_fit.py`, roadmap R8/P4.5): the standard GEH statistic (with the zero/zero edge case handled), travel-time RMSE and MAPE, and a summary helper reporting how many links pass the conventional GEH < 5 threshold. Tested on synthetic counts; a future calibration report (P4.7) would consume this.
- Turn-restriction transform (`arteria/interventions/turn_restriction.py`, roadmap R18/P5.2): removes a named connection from a `.net.xml`-shaped document without mutating the input, and reports whether the two edges stay connected through some other path afterward (a minimal stand-in for the fuller P5.4 validity checks). Tested on a toy fixture with both a bypassed and a sole connection.
- One-way conversion transform (`arteria/interventions/one_way.py`, roadmap R18/P5.2): removes a directional edge of a two-way pair from a `.net.xml`-shaped document (plus its now-dangling connections) without mutating the input, and reports which junctions, if any, become unreachable from the rest of the network as a result. Tested on a toy fixture with both a bypassed removal and one that strands a dead-end side branch.
- Lane vehicle-class restriction transform (`arteria/interventions/lane_restriction.py`, roadmap R18/P5.2): sets a lane's `allow` vClass list on a `.net.xml`-shaped document and clears any conflicting `disallow`, without mutating the input — the one mechanic behind several catalog entry types (bus lane, protected bike corridor, pedestrian lane, car-to-bike/ped lane reallocation), distinguished only by the `allow` list passed in. Reports the lane's previous `allow`/`disallow` values so a caller can see exactly what traffic is displaced. Tested on a toy fixture covering both an unrestricted lane and one that already carried a `disallow`.
- Induction-loop detector mapping (`arteria/calibration/detectors.py`, roadmap R8/P4.2): maps a list of count-observation locations (edge + position) onto a `.net.xml`-shaped network, emitting a `<inductionLoop>` per lane of each matched edge into an `.add.xml`-shaped document, with unmatched edges and out-of-range positions (clamped to fit the lane) flagged separately. Tested on a toy fixture with multi-lane edges, an unknown edge, and an out-of-range position.
- Stochastic replication and confidence-interval helpers (`arteria/calibration/replication.py`, roadmap R8/P4.6): mean, sample standard deviation, standard error, and a normal-approximation confidence interval across a metric's per-seed values, plus a convergence check (whether the CI half-width is within a relative tolerance of the mean). Documented as an informal approximation (no Student's-t, to avoid a scipy dependency), not yet a fully rigorous academic CI. Tested on hand-checked synthetic series.
- Evaluation metric library core (`arteria/evaluate/metrics.py`, roadmap R18/P6.2): turns a sequence of trip records (duration, route length, waiting time, time loss — the fields a real `tripinfo.xml` carries) into VHT, VKT, mean and P95 travel time, mean delay, and total waiting time. Operates on already-parsed records only; parsing a real `tripinfo.xml` is future work. Tested on hand-computed synthetic trips.
- Intervention catalog schema (`arteria/interventions/catalog.py`, roadmap R17/P5.1): a pydantic schema for one candidate street intervention per catalog entry (type, target edges/junctions, free-form transform parameters, cost estimate, complexity, legal/safety/equity notes, expected beneficiaries/losers, and which other entries it can't coexist with), with a load-time check that every `mutual_exclusions` reference is to a real, different entry. **[ADR 0006, Proposed]** records why `parameters` stays a free-form dict and constraints stay free text for now, rather than a per-type sub-schema or a machine-checkable rules engine.
- `arteria osm fetch` / `arteria network build` / `arteria network validate` (`arteria/network/osm_fetch.py`, `arteria/network/build.py`, roadmap P2.1/P2.2/P2.3/P2.5, remote task R4, desk tasks L8/L9/L11): fetches (or reuses a cached) regional OSM extract, clips it to a study-area candidate's polygon via `osmium extract`, runs `netconvert` with the standard SUMO OSM-import flag set, and validates the result with the existing `validate_network()`. Every external call (download, `osmium`, `netconvert`) sits behind an injected callable per ADR 0009 and is tested only against fakes and toy fixtures — none of it has run against the real binaries or real SJC data yet. `docs/local/sjc-quickstart.md` is the desk runbook that chains these into a first real SJC network render plus uncalibrated traffic via SUMO's `randomTrips.py`.
- Study-area polygon drafting (`arteria studyarea build`, `arteria/network/study_area.py`, roadmap P1.4): geocodes a candidate's landmark list via Nominatim, builds a buffered convex-hull polygon, and writes it as GeoJSON. The geocoding call is the only part that touches the network (blocked in remote sessions, ADR 0009) — written and tested here against fixture coordinates; the real run, against `cities/sjc/study-areas.yaml`'s 4 SJC candidates (priority B > D > C > A, per the owner's 2026-10-25 decision), happens at the desk. Output is a draft, meant to be checked against satellite imagery/OSM before any real P2.1 extraction.
- Signal-retiming transform (`arteria/interventions/signal_retiming.py`, roadmap R18/P5.2): sets each `<phase>` duration on a named `<tlLogic>` in a `.net.xml`-shaped document, in existing phase order, without mutating the input, and reports the previous and new cycle length. Only changes durations — phase count, order, and `state` strings are untouched; transit signal priority stays a separate, deferred transform pending the detector/TraCI wiring it needs. Tested on a toy fixture with a 2-phase traffic light.
